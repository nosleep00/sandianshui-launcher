## 1. 项目概述

### 1.1 什么是 Minecraft 启动器（给零基础的解释）

Minecraft（我的世界）Java 版的游戏本体，是一堆需要按特定规则摆放的文件（游戏主程序、依赖库、资源文件、Java 运行环境等）。玩家不能直接双击这些文件来玩，必须用一个程序完成以下工作：

1. 帮玩家**下载**游戏文件（或从指定镜像下载）；
2. 管理多个游戏版本、Mod、整合包；
3. 处理**登录**（确认玩家身份）；
4. 拼出一条很长的 Java 启动命令，调用 Java 运行环境**启动游戏**；
5. 管理游戏设置（内存、窗口、Java 参数等）。

这个程序就是"启动器"。官方启动器下载慢、功能简单，因此国内出现了 PCL2、HMCL、BakaXL 等第三方启动器。

### 1.2 参考产品 PCL2 简介

PCL2（Plain Craft Launcher 2）是国内作者龙腾猫跃开发的免费第三方启动器，仅支持 Windows，核心特点：

- 多线程快速下载，支持国内镜像源（BMCLAPI 等）；
- 从远古版本到最新正式版、快照版的游戏下载；
- 一键安装 Forge、NeoForge、Fabric、Quilt、LiteLoader、OptiFine 等模组加载器；
- 内置 Mod、整合包搜索（CurseForge、Modrinth），支持拖拽安装与冲突检测；
- 支持微软正版账号、离线账号、外置登录（如 LittleSkin）；
- 版本隔离、存档/截图管理、崩溃分析、高度自定义主题。

本项目以 PCL2 的功能为参考蓝本，但**不照搬代码与界面**，从零实现属于自己的启动器。

### 1.3 产品目标

**做什么（项目范围内）：**

- 面向 Windows 10 / 11 普通玩家；
- 实现"下载 → 管理 → 登录 → 启动"的完整闭环；
- 下载源地址可配置（具体镜像源由项目所有者后续提供）；
- 先做中文界面，架构上预留多语言能力。

**暂时不做（范围外）：**

- 不做游戏破解，不绕过正版验证；离线模式仅提供身份占位，不提供盗版联机；
- 不做 macOS / Linux 版本（首版）；
- 不自己分发游戏本体文件（只做"下载引导"，文件来自官方或项目所有者指定的下载源）；
- 不做游戏内作弊、外挂相关功能。

### 1.4 目标用户

| 用户类型 | 特征 | 核心诉求 |
| --- | --- | --- |
| 新手玩家 | 不懂 Java、不懂文件结构 | 一键下载、一键启动，出问题看得懂提示 |
| 模组玩家 | 玩 Forge/Fabric 整合包 | 加载器安装、Mod 管理、版本隔离 |
| 多账号玩家 | 有正版号也有离线/外置号 | 快速切换账号 |
| 怀旧玩家 | 玩 1.7.10 等老版本 | 老版本能下载、能正常启动 |

## 2. 名词解释（零基础必读）

| 名词 | 通俗解释 |
| --- | --- |
| **Java 版** | Minecraft 基于 Java 语言编写的版本，PCL2、HMCL 等启动器服务的就是这个版本（与手机版/基岩版不是一回事） |
| **正式版 / 快照版** | 正式版是稳定发布版本（如 1.21.x）；快照版是每周预览测试版（如 25wxx） |
| **Java 运行环境（JRE/JDK）** | 运行 Java 版游戏所必需的"发动机"，不同游戏版本需要不同大版本的 Java（老版本用 Java 8，新版本用 Java 17/21） |
| **libraries（依赖库）** | 游戏运行所依赖的一堆 .jar 文件 |
| **assets（资源文件）** | 游戏的音效、语言、贴图索引等资源 |
| **natives（原生库）** | 与操作系统相关的底层文件（如 .dll），启动时需要解压 |
| **版本 JSON** | 每个游戏版本的"清单文件"，记录该版本需要下载哪些文件、启动参数怎么拼 |
| **Mod（模组）** | 玩家或社区制作的游戏扩展内容，如小地图、光影前置、新物品 |
| **模组加载器** | 让 Mod 能被加载运行的"底座"，主流有 Forge（老牌、Mod 多）、NeoForge（Forge 新分支）、Fabric（轻量、新版本更新快）、Quilt（Fabric 分支）、LiteLoader（老牌轻量）、OptiFine（光影优化） |
| **整合包（Modpack）** | 作者搭配好的一整套 Mod + 配置，导入后即可玩，常见格式为 CurseForge、Modrinth（mrpack） |
| **资源包 / 光影 / 数据包** | 资源包改贴图与界面，光影改画面光影效果，数据包改游戏规则与内容 |
| **离线账号** | 不联网验证、由玩家自取用户名的模式，只能玩单人游戏和离线服务器 |
| **微软正版账号** | 购买了正版后用微软账号 OAuth 登录，可进正版服务器、同步皮肤 |
| **外置登录** | 通过 authlib-injector 加载第三方认证服务器（如 LittleSkin），用于皮肤站与第三方服务器 |
| **版本隔离** | 让每个游戏版本拥有独立的 Mod、存档、截图目录，互不干扰 |
| **下载源 / 镜像站** | 游戏文件在官方服务器上，国内下载慢；镜像站（如 BMCLAPI）做了一份同样的文件供国内加速。本项目的镜像地址由项目所有者后续提供 |
| **崩溃分析** | 游戏崩溃时读取日志，判断是 Mod 冲突、Java 版本不对还是内存不足，并用大白话提示 |

## 3. 功能需求

### 3.1 功能优先级总览

优先级定义：

- **P0（MVP 必须有）**：没有它就不构成启动器，第一版必须完成；
- **P1（重要）**：完成 P0 后尽快补齐的核心体验；
- **P2（锦上添花）**：个性化与高级功能，后期再做。

| 编号 | 功能模块 | 优先级 | 说明 |

| F1 | 启动主页 | P0 | 选版本、选账号、点"启动游戏" |
| F2 | 账号管理（离线） | P0 | 先支持离线账号，正版登录放 P1 |
| F3 | 游戏版本下载 | P0 | 从配置的下载源拉取版本清单并下载原版游戏 |

| F19 | 设置中心 | P1 | 下载源、线程数、代理、语言 |

### 3.2 各功能模块详述

#### F1 启动主页（P0）

- 顶部/侧边显示当前账号头像与名称，可点击切换；
- 显示当前选中的游戏版本（含加载器标记，如"1.21.1-Fabric"）；
- 显眼的"启动游戏"按钮，点击后显示下载缺失文件（如有）→ 启动进度（解压原生库、登录、构造参数）→ 游戏窗口打开后启动器自动最小化或保持；
- 可放公告/帮助入口（P2 再做）。

#### F2 账号管理（P0 先做离线，P1 补正版与外置）

- **离线账号（P0）**：输入用户名（3–16 位合法字符），自动生成一个本地 UUID（离线模式规则），无需联网；
- **微软正版登录（P1）**：使用微软官方 OAuth2 设备码流程登录（启动器显示一组代码 → 浏览器打开微软页面授权 → 启动器自动完成登录），换取游戏访问令牌，令牌过期可静默刷新；
- **外置登录（P1）**：填写认证服务器地址（如 LittleSkin），通过 authlib-injector 机制注入认证；
- 多账号列表，支持添加、删除、快速切换；账号令牌必须加密存储在本地，不得明文保存。

#### F3 游戏版本下载（P0）

- 启动器从"版本清单地址"（下载源配置，**地址待项目所有者提供**）获取全部版本列表；
- 分类展示：正式版、快照版、远古版，可搜索、按版本号筛选；
- 选择某版本后，按版本 JSON 下载：游戏主 jar、libraries、natives、assets 资源索引及资源文件；
- 支持下载 Forge/Fabric 等修改过的版本（继承原版 JSON，见 F10）；
- 下载前展示文件大小，下载中可取消；
- 已下载的版本标记"已安装"，支持重新下载/修复。

#### F4 启动核心（P0）

启动器最关键的模块，按顺序完成：

1. 读取目标版本的版本 JSON（加载器版本会通过 `inheritsFrom` 继承原版 JSON，需要合并）；
2. 校验本地文件完整性（哈希校验），缺失文件先补下载；
3. 解压 natives 原生库到临时目录；
4. 拼接 classpath（所有 libraries 的 jar + 游戏主 jar）；
5. 根据账号类型取得启动参数（用户名、UUID、访问令牌、用户类型）；
6. 处理新旧版本参数模板差异（1.13+ 使用 `arguments` 节点，老版本使用 `minecraftArguments` 字符串）；
7. 调用匹配版本的 Java 运行游戏，接管游戏进程；
8. 输出游戏日志，游戏退出后记录退出码（崩溃时进入 F17 分析）。

#### F5 Java 检测与管理（P0）

- 首次启动自动扫描常见安装位置与注册表、PATH 中的 Java；
- 展示检测到的 Java 版本与路径；
- 规则提示：1.17.1 及更早用 Java 8；1.18–1.20.4 用 Java 17；1.20.5+ 用 Java 21（具体以版本 JSON 要求为准）；
- 找不到合适 Java 时，提供一键下载入口（下载地址同样走配置的下载源）。

#### F6 下载管理器（P0）

- 多线程并发下载（线程数可配置，默认 16–64）；
- 任务队列、总进度与单文件进度、实时速度；
- 失败自动重试（可配置次数），支持从断点续传；
- 先下载到 `.tmp` 临时文件，完成并校验哈希后再移动到正式位置，避免半成品文件；
- 关闭启动器后未完成任务下次可继续。

#### F7 版本管理（P1）

- 已安装版本列表：重命名、复制、删除（删除前二次确认）；
- 版本隔离开关：开启后每个版本使用独立的 `saves`、`mods`、`screenshots` 等目录；
- 导出版本信息，便于分享整合包。

#### F10 模组加载器安装（P1）

- 支持 Forge、NeoForge、Fabric、Quilt 的版本列表获取与一键安装（数据走配置的下载源）；
- Forge 老版本需要运行安装器（installer）处理流程，新版本与 Fabric 直接生成版本 JSON；
- OptiFine、LiteLoader 可作为 P2 支持。

#### F11 Mod 管理（P1）

- 读取对应版本的 `mods` 文件夹，列出 Mod（读取 jar 内元数据：名称、版本、作者、简介）；
- 启用/禁用（禁用文件改为 `.jar.disabled`）、删除、打开 Mod 文件夹；
- 拖拽 jar 进窗口即可安装；
- 依赖缺失与版本不匹配时给出提示。

#### F12 整合包导入导出（P1）

- 导入 CurseForge（zip）与 Modrinth（.mrpack）整合包：解析清单 → 创建隔离版本 → 按下载源下载 Mod 与配置；
- 导出当前版本为整合包（遵守第三方平台规则，不打包受版权保护的 Mod 文件本体，只写清单）。

#### F13 资源下载（P2）

- 对接 Modrinth / CurseForge 等公开 API（需在设置中配置或内置），搜索 Mod、资源包、光影、数据包、皮肤、地图；
- 注意：这些平台 API 可能在国内访问不稳定，需考虑代理/镜像，作为 P2 风险点。

#### F14 存档与截图管理（P2）

- 列出存档：名称、最后游玩时间、游戏模式，支持备份为 zip、删除、打开文件夹；
- 截图预览、打开目录、批量导出。

#### F15 启动设置（P0 基础项 / P1 高级项）

- P0：内存分配（滑块，默认按物理内存给出建议值）、Java 路径选择、游戏目录；
- P1：窗口宽高、全屏、JVM 额外参数、游戏参数（如快速加入服务器 `--server`）、Java 高级参数、版本隔离默认值。

#### F16 个性化主题（P2）

- 背景图/背景纯色、主题色强调、浅色/深色模式；
- 参考 PCL2 的可自定义程度，但首版只做 2–3 套内置主题。

#### F17 崩溃日志分析（P2）

- 游戏异常退出后读取 `logs/latest.log` 与崩溃报告；
- 用规则匹配常见问题：Java 版本不匹配、内存不足、Mod 重复/冲突、缺少前置、显卡驱动过旧等，给出中文解决建议。

#### F19 设置中心（P1）

- 下载源配置（版本清单、库、资源、Java 下载的基础地址模板）——**核心配置，地址由项目所有者提供**；
- 下载线程数、重试次数、网络代理（HTTP/SOCKS）；
- 语言、启动器数据目录、缓存清理、关于页面。

## 4. 非功能需求

| 类别 | 要求 |
| --- | --- |
| 系统兼容 | Windows 10 1809 及以上、Windows 11；64 位系统优先（32 位仅做兼容评估） |

| 可维护性 | 模块化分层（下载、启动、账号、UI 分离），所有下载地址走统一配置，不硬编码 |
| 体积 | 安装包目标控制在 30 MB 以内（不含 Java 与游戏本体） |

## 5. 技术选型建议

### 5.1 主流第三方启动器的技术栈参考

| 启动器 | 技术栈 | 特点 |
| --- | --- | --- |
| PCL2 | VB.NET + WinForms | 仅 Windows，体积小、界面控件靠 GDI+ 自绘 |
| HMCL | Java + JavaFX | 跨平台，开源，资料多 |
| BakaXL 4.x | Vue + TypeScript + Tauri（Rust） | 界面现代，但技术链复杂 |
| MultiMC / PrismLauncher | C++ + Qt | 跨平台、性能好，学习门槛高 |

### 5.2 推荐方案：C# + .NET（WPF）

**推荐给零基础开发者的组合：**

- **语言**：C#（语法比 VB.NET 更主流，中文教程多，与 Java 概念容易对照）；
- **框架**：.NET 10（实际采用；代码仅用跨版本通用 API，亦可回退到 .NET 8 LTS 长期支持版）；
- **界面**：WPF（XAML 写界面，数据绑定方便做现代化界面；Visual Studio 自带可视化设计器）；
  - UI 控件库：WPF-UI 4.3（Fluent 风格暗色主题）；
  - MVVM 框架：CommunityToolkit.Mvvm 8.4（`ObservableObject`/`RelayCommand`，实现界面与逻辑解耦）；
- **开发工具**：Visual Studio 2022 社区版（免费）或更新版本；
- **数据格式**：System.Text.Json 处理版本 JSON（Minecraft 生态全部是 JSON）；
- **HTTP 下载**：基于 HttpClient 自行实现的多线程下载器（支持并发、断点续传、失败重试、SHA1 校验、整体进度统计）。

**为什么不推荐其他方案：**

- **WinForms**：PCL2 同款，入门更简单，但自定义美观界面很痛苦（PCL2 大量自绘代码），不推荐新项目；
- **Java/JavaFX**：界面打包体验一般，且你做的是 Java 游戏的启动器，用 Java 写容易和游戏自身环境概念混淆；
- **Tauri/Web 技术**：界面好看，但需要同时学前端三件套 + Rust，对零基础是双倍难度，可作为未来重构方向。

### 5.3 需要攻克的关键技术点（实现阶段再深入，此处只做认知）

1. **版本 JSON 解析与合并**：原版版本 JSON 与加载器版本 JSON（`inheritsFrom`）的递归合并；
2. **下载源替换**：官方下载地址（`piston-meta.mojang.com`、`libraries.minecraft.net`、`resources.download.minecraft.net`）按规则整体替换为镜像基础地址，替换规则必须集中在一个模块里，便于切换你提供的下载源；
3. **assets 资源机制**：按资源索引文件（hash 前两位做目录）下载对象文件；
4. **启动参数构造**：classpath 分隔符（Windows 用 `;`）、natives 路径、新旧参数模板、新版 Java 模块参数（`--add-opens` 等）；
5. **微软登录链**：OAuth2 设备码 → Xbox Live 登录 → XSTS 令牌 → Minecraft 服务登录 → 校验游戏所有权 → 获取玩家资料；
6. **外置登录**：authlib-injector 的 javaagent 参数与认证 API 对接；
7. **进程管理**：启动后监听游戏进程退出、实时读取日志输出。

### 5.4 可参考的开源项目（学习思路，不复制代码）

- **HMCL**（Java，GPL 协议）：功能最全，启动流程、加载器安装逻辑最值得对照学习；
- **PrismLauncher / MultiMC**（C++/Qt）：版本管理与启动流程的工程化参考；
- 开源协议注意：参考可以，但复制 GPL 代码到自己的项目后，自己的项目也必须开源并遵守对应协议。

## 6. 界面结构规划

首版采用 PCL2 风格的**左侧导航 + 右侧内容区**布局：

```
┌─────────────────────────────────────────────────────┐
│  顶部栏：当前账号头像/名称 ▾   窗口控制（最小化/关闭）│
├────────────┬────────────────────────────────────────┤
│            │                                        │
│   ▶ 启动   │                                        │
│   ⬇ 下载   │            内容区（随导航切换）         │
│   ▦ 版本   │                                        │
│   ⚙ 设置   │                                        │
│            │                                        │
├────────────┴────────────────────────────────────────┤
│  底部状态栏：下载进度 / 网络状态 / 版本号             │
└─────────────────────────────────────────────────────┘
```

各页面：

- **启动页**：背景大图 + 中央大按钮"启动游戏" + 版本选择下拉 + 账号区；
- **下载页**：选项卡（游戏 / 加载器 / Mod / 整合包，后两个随阶段开放），版本列表 + 搜索框；
- **版本页**：已安装版本卡片，支持重命名、删除、版本设置、Mod 管理入口；
- **设置页**：游戏设置（内存、Java、目录）、账号管理、网络与下载源、个性化、关于。

弹窗：启动进度窗口、登录窗口、崩溃报告窗口。

## 8. 开发路线图（零基础友好，每阶段都有可运行成果）

> 原则：每个阶段结束都要能编译出一个可运行的程序，并在 Git 中打标签；每完成一个阶段做一次完整验证。

| 阶段 | 目标 | 主要任务 | 验收标准（可运行成果） |
| --- | --- | --- | --- |
| **阶段 0：环境与基础** | 把开发环境跑通 | 安装 Visual Studio；新建 WPF 项目并学会调试、打包；学习 C# 基础语法、XAML 布局、Git 基本操作 | 能运行一个带按钮的空窗口，点击按钮弹出"你好" |
| **阶段 1：最小启动器 MVP** | 启动一个现成版本 | 手动放置一个离线版本文件夹；实现：离线账号界面 → 解析版本 JSON → 固定拼接启动命令 → 调用本机 Java 启动游戏 | 选一个用户名、点启动，能打开 Minecraft 主菜单（1.16 与 1.20 各验证一个版本） |
| **阶段 2：游戏下载** | 自动下载游戏 | 对接版本清单（**使用项目所有者提供的下载源**）；实现多线程下载器、assets/libraries/natives 下载、哈希校验 | 不预装任何游戏文件，纯靠下载安装一个正式版并成功启动 |
| **阶段 3：Java 与启动完善** | 启动器变可靠 | Java 自动检测、版本匹配规则、内存设置、新旧参数模板兼容、文件完整性校验/修复 | 一台没装过 Java 的电脑上也能完成下载并启动 |
| **阶段 4：账号系统** | 支持正版与外置 | 微软 OAuth 全流程、令牌刷新、外置登录；账号加密存储 | 正版账号登录成功并显示皮肤，可进正版服务器；外置账号可登录 |
| **阶段 5：加载器与 Mod** | 模组玩家可用 | Forge/NeoForge/Fabric/Quilt 安装、版本隔离、Mod 启用/禁用、拖拽安装 | 下载一个 Fabric 版本并安装 2 个 Mod 成功运行 |

| **阶段 7：体验完善** | 向 PCL2 看齐 | 主题、存档/截图管理、崩溃分析、资源下载、启动器自更新 | 形成可对外发布的 v1.0 |

每个阶段都要遵循 AGENTS.md 的要求：改动完成后提交 Git commit，并先在本机验证通过再进入下一阶段。

## 9. 法律与合规注意事项

1. **Minecraft 是 Mojang/微软的商业软件**：启动器本身合法（PCL2、HMCL 均公开存在），但不得随启动器分发游戏本体文件、不得提供破解；
2. **下载源责任**：项目所有者提供的下载源必须是有权使用的镜像（官方地址或获得授权的镜像站），启动器只做地址配置与下载，不内置盗版文件；
3. **微软登录必须走官方 OAuth 流程**：需要在微软 Azure 注册应用获取 Client ID（HMCL 等有公开申请流程可参考），不得抓取、转存他人账号密码；
4. **Mod 与整合包**：CurseForge、Modrinth 上的作品各有其许可协议，导出整合包时只写清单、不打包限制再分发的文件；
5. **开源协议**：参考他人代码时遵守对应协议（GPL 系传染性、MIT 较宽松），本项目自身的开源/闭源策略待定。
